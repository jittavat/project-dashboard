# /project:update-project

Scan the project and keep `CLAUDE.md` and `.claude/skills/` in sync with the actual codebase.

**Arguments:** `$ARGUMENTS`

Supported flags (space-separated, any order):
- *(no flag)* — update `CLAUDE.md` only
- `--skills` — update `CLAUDE.md` **and** create/update all skill files
- `--skills-only` — update skill files only, leave `CLAUDE.md` untouched
- `--skill <name>` — create or rewrite a single named skill (e.g. `--skill sqlx-workflow`)

---

## Step 1 — Read the project state

Read these files to understand the current project (read them in parallel):

- `CLAUDE.md` — what's already documented
- `Makefile` — canonical command list
- `backend/Cargo.toml` — exact crate versions and feature flags
- `frontend/package.json` — npm scripts and dependency versions
- `docker-compose.yml` — service names, ports, env-var defaults
- `backend/src/main.rs` — server setup, middleware wiring
- `backend/src/routes.rs` — all registered routes and OpenAPI spec
- `backend/src/errors.rs` — `AppError` variants
- `backend/src/middleware/auth.rs` — `CurrentUser` extractor
- `backend/src/models/ticket.rs` — representative model struct
- `backend/src/handlers/tickets.rs` — representative handler patterns
- `frontend/src/api/index.ts` — axios client, interceptors
- `frontend/src/router/index.ts` — route guard, lazy-load pattern
- `frontend/src/types/index.ts` — TypeScript types
- `frontend/src/stores/tickets.ts` — representative Pinia store

Also list `.claude/skills/` to see which skills already exist.

---

## Step 2 — Update CLAUDE.md (skip if `--skills-only`)

Rewrite `CLAUDE.md` using **only facts you can verify from the files you just read**. Do not invent features, commands, or file paths.

The file must follow this structure exactly:

```
# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

### Full stack (Docker)
<make targets with one-line descriptions, from Makefile>

### Backend (Rust) — requires DATABASE_URL
<cargo commands with flags, from Cargo.toml + Makefile>

### Frontend (Vue)
<npm scripts, from package.json>

## Architecture

### Backend (`backend/src/`)
<single paragraph or bullet list — server, DB, auth, handlers, errors>
<Include any non-obvious invariants: AppError::NotFound signature, query_as! import rule, SQLX_OFFLINE>

### Frontend (`frontend/src/`)
<single paragraph or bullet list — router, stores, api client, key views>
<Include any non-obvious invariants: camelizeKeys interceptor, 401 redirect, store initialize()>

### Auth flow
<numbered steps>

### Docker Compose services
<table: Service | Port | Notes>

### Environment variables
<table or description of all vars with defaults>

## graphify
<keep existing graphify section verbatim — do not modify it>

## Skills
<auto-generated index of .claude/skills/ — one line per skill: trigger, description>
```

Rules for updating:
- Preserve the `## graphify` section exactly as-is.
- If a section already exists and is still accurate, keep it; only rewrite stale parts.
- Remove sections that describe things no longer in the code.
- Add sections for things in the code not yet documented.
- Keep descriptions short — this file is for Claude, not human readers.

## Step 3 — Update skills (skip if no `--skills` or `--skills-only` flag; or if `--skill <name>`, only write that one)

For each skill in `.claude/skills/`, read its current `SKILL.md` then decide: **accurate, stale, or missing**.

Skill files to check and their scope:

| Skill | What it covers |
|---|---|
| `sqlx-workflow` | Migrations, `query_as!`, offline cache, error table |
| `rust-actix-scaffold` | Handler pattern, route registration, `CurrentUser`, error handling |
| `vue3-vite-scaffold` | New view/store/API module patterns, `camelizeKeys`, test template |
| `docker-fullstack` | `make dev`, env-var override, postgres healthcheck, nginx proxy |
| `vitest-vite-split` | Why `vitest.config.ts` exists separately, `mergeConfig` pattern |

For each skill that is stale or if a new skill is needed:

1. Read the relevant source files for that skill's domain.
2. Rewrite (or create) `.claude/skills/<name>/SKILL.md` using this frontmatter:

```markdown
---
name: <slug>
description: <one sentence — what Claude should know before editing this area>
trigger: /<slug>
---
```

Followed by concise, accurate markdown. Include:
- Why this pattern exists (the non-obvious constraint)
- Code snippets showing the exact pattern in this project
- A "Diagnosing errors" table if applicable
- No more than ~150 lines total

**Do not fabricate crate versions, file paths, or API surface.** If unsure, read the source.

---

## Step 4 — Report

Print a brief summary:
- What changed in `CLAUDE.md` (or "no changes needed")
- Which skills were created / updated / unchanged
- Any stale information removed
